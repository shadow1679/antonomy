# Antonomy design system (v0)

Code lives in `web/ds/`. Link `antonomy.css` and you get tokens, base styles and components. To see every component with working states, run `python3 -I -m http.server -d .` from the repo root and open `/web/ds/showcase.html`. The repo root has to be served because the showcase imports the real sim from `sim/js/antosim.mjs`.

## Decisions

| Area | Choice | Why |
|---|---|---|
| Theme | Underground nest: dark soil, bone text, pheromone amber | Ties the UI to the sim and keeps the canvas as the main element |
| Colour mode | Dark only | One mode to build and contrast-check within the 14-day window |
| Format | Plain CSS custom properties and classes, no build step | The replay page is static and hosted for free |
| Type | Fraunces for headings and prose, IBM Plex Mono for UI, data, seeds and hashes | Display serif for character, mono for anything you compare or verify |
| Option colours | Earth palette (moss, clay, slate, heather, sand), each paired with a glyph | On-theme. Tuned to stay distinguishable under colour-blindness simulation |
| Shape | Organic-soft: radii 6 / 10 / 16, chambers as cards | Reads as nest chambers |
| Motion | Subtle: 120 / 200 / 360 ms, a pulse on live, a short reveal on verify | All motion stops under `prefers-reduced-motion` |

## Files

- `tokens.css` holds raw scales (`--soil-*`, `--bone-*`, `--amber-*`, status, `--opt-0..4`) and semantic aliases (`--bg`, `--surface`, `--text`, `--accent` and so on). **Components use only the aliases.**
- `base.css` has the reset (including `[hidden] { display: none !important }`, so `hidden` beats any component's display), body, headings, `.prose`, text utilities and layout helpers (`.container`, `.stack`, `.cluster`, `.grid-auto`).
- `components.css` has every component listed below.
- `colony-view.mjs` is the sim canvas renderer (scenery, ants, effects). It imports the sim constants from `sim/js/antosim.mjs`.
- `colony-thumb.mjs` is a small, cheap colony view for overview cards (trail, glyph piles, ant dots).
- `antonomy.css` is the entry point. It loads Google Fonts and then the three files above. Without network, the font stacks fall back to system serif and mono.

## Rules

1. **Amber is reserved.** It means pheromone, the brand and the one primary action in a view. Never use it for an option or a status.
2. **Every option shows its glyph next to its colour** (▲ ■ ◆ ● ★ for options 0 to 4). Use `data-opt="n"` together with `.opt`. Never show an option by colour alone.
3. **Status needs a glyph and a word.** Examples: ✓ Hash match, ✗ Hash mismatch, ▲/▼ for deltas. Colour only reinforces the message.
4. **Hashes and seeds are always mono, copyable, and show their full value on hover** (`.hash` with a `title` and a `.hash__copy` button carrying `data-copy`). When truncating, keep the start and the end, as in `0x9f3a5c07…a3d9e21c`.
5. **Every forecast output carries `.tag-forecast`** ("Forecast · not advice"). Label the averaged number "Swarm belief" until calibration exists. Never link to trading venues.
6. **The colony picks an index, never an amount.** Menus render as `.option-card` radios with fixed values and show the cap.
7. **Wallet tints** use `oklch(0.72 0.07 h)`, where h is the first 2 bytes of sha256(account id) mod 360. Lightness and chroma are fixed so staker ants never outshine trails or food. Use `.wallet` with an inline `--wallet-hue`. Canvas code uses the same numbers. A **spotlight** is the one way to make a wallet's ants stand out, and only on request: hovering or pinning a roster row sets `ColonyView.spotlight`, which puts a halo in the wallet's tint under its ants and (with `dimOthers`) fades the rest to 28%. The tint itself never changes.
8. **Sim canvas colours:** soil scenery in `--soil-*` only, so it never competes with data. Pheromone is amber, running from `--amber-600` (weak) to `--amber-300` (strong), with alpha scaled to intensity. Food piles use `--opt-n`, and a label with the glyph sits on each pile. Ants are bone (or their wallet tint later) with a dark halo for contrast. A returning ant carries a crumb in the colour of the pile it visited.
9. **Scenery is decoration.** `colony-view.mjs` draws soil, roots, pebbles and the anthill from its own PRNG keyed by the seed. It only reads `Colony` state and never calls the sim RNG. The **Cells** view drops the scenery and shows the grid one pixel per cell, for anyone checking the raw trail.
10. **Canvas motion:** ants move smoothly between ticks with a six-leg gait, the scoring rings' dashes march while playing, crumbs pop at pickup and sink into the nest, and the winning pile ripples at tick 800. Under `prefers-reduced-motion`, ants snap to cells and none of these effects run.

## Contrast (WCAG, checked on `--surface-raised`, the lightest surface)

| Token | Ratio | Use |
|---|---|---|
| `--text` | 12.8 | Body |
| `--text-muted` | 7.0 | Secondary text |
| `--text-faint` | 4.8 | Labels, hints (passes AA) |
| `--accent` | 7.7 | Amber text and icons |
| `--on-accent` on amber | 9.1 | Primary button label |
| `--border-strong` on chamber | 3.3 | Input borders (passes the 3:1 rule for non-text UI) |
| `--opt-0..4` | 4.5 or more | Option glyphs and bars |

Options under colour-blindness simulation (Machado 2009 at full severity, then pairwise OKLab distance): the closest pair is moss and clay under deuteranopia, at ΔE 0.092. Any palette change must keep every pair at 0.08 or more under deutan, protan and tritan, and keep the glyphs regardless.

## Page layout (`web/app.css`)

- **Shell.** `topbar()` and `footer()` in `web/ui.mjs` build every page's header and footer. The nav groups the doing pages (Live, Burn, Recruit, Sandbox) apart from the checking pages (Replay, Receipts), with Docs on its own at the end. A slim `.demo-strip` says there is no contract yet; Sandbox leaves it out because it never touches the chain. Tabs run the bar's full height and the current page carries an amber rule on the bar's bottom edge. The footer has the brand and the not-advice line, the pages in the nav's groups (Take part; Check & learn), the known limits, and a base row with the network, sim version and contract. Under 760px the nav becomes its own scrollable row, scrolled so the current tab shows, and the top bar stops being sticky.
- **Page head.** Every page uses `.page-head__split`: eyebrow and title on the left, a lede of at most three lines on the right, bottoms aligned; one column under 1000px. On the Burn page, which has a `.day-strip`, the lede hides on phones. Live uses its own round bar (below).
- **Landing** (`web/index.html`, `topbar("home")`). `.hero`: the pitch, the one primary action (Watch the live colonies) and three `.hero__facts`, beside `.hero__live`, a chamber with the current round's first market live (Momentum map, compact belief board, `.tag-forecast`). Then what the colonies do: `.steps--four` (trending market, odds on-chain, three colonies forage, one swarm belief) and `.forecasters`, one card per forecaster with what it reads, its rule, its colony as a `ColonyThumb` and its live leader. Then `.tour`, five numbered cards that turn to ✓ with the word "done" once followed, and `.roles` (holders, agents). It explains only as much as gets a newcomer to a page; the rest links to Docs.
- **Live** (`web/live.html`) and **Market** (`web/market.html`), with their own sheet `web/live.css`, scoped to `body.lv`; shared helpers in `web/lv.mjs`. Both pages have their own look on top of the tokens: IBM Plex Sans for UI and prose, mono only for numbers, ids, hashes and status glyphs (`.lv-g`, since the sans has no ◌), Fraunces only for the page, section and market titles; flat `.lv-panel`s with hairlines instead of raised chambers. The shell (top bar, demo strip, footer) keeps its mono. It opens on the **round bar** (`.lv-round`): round number and a one-line lede, the five steps as segments (`.lv-steps`, the current one amber, past ones ✓), the one clock that matters (`.lv-clock`: staking closes, the agents' window ends, cranks done), then one status line, the seed, receipts once there is a run, the crank button only while cranking is possible, and a limits link. Then **Markets**: one card per market (`.lv-cards`, `.lv-card`, two columns, one on phones), six to a page with a pager (`.lv-pager`: previous, numbered pages, next). A card shows the number, title (the one link; the whole card opens it), status, the leader with its share and gap to the market, one stacked bar of every outcome (`.lv-stack`, a glyph on each wide segment, the breakdown as hidden text and a title), and the three colonies as mini maps (`.lv-cols`, a `ColonyThumb` each, replayed from the on-chain seed while the card is on screen, with each colony's leading option and `out` when it sits out). Before the seed there are no maps: each slot shows the bare plot with the colony idling (`ColonyThumb.drawIdle(kind, t)`: soil, a faint grid, the nest breathing, and nine bone scouts on a path that hints at the colony's rule: Momentum surging one way that drifts, Community crowding the nest, Agents in three squads; pure functions of the clock in `idleScout`, never the sim RNG; no food and no amber, since nothing has been read; drawn only while the card is on screen, one still frame under reduced motion) with what that colony will read (`.lv-cols--idle`), and the card's sub-line says when the maps come. The previous round's cards follow under their own head, with their own pager, while the current round has no run. Requested forecasts use dense rows (`.lv-rows`, `.lv-row`) and link to the Recruit page; Today's burn is one strip (`.lv-burn`) with no amber button. A card opens the **market page** (`market.html?m=<key>`, `m3` this round, `p3` the previous one; old `live.html#market-<key>` links redirect): a slim round bar (`.lv-round--slim`) with the way back, then the market (`.lv-market`): previous / next within the round (swapped in place), belief board and **Your part** (`.lv-act`, `.seg` tabs Stake | Post odds, acting on this market's colony) on the left; before the seed, the three colonies idling in the tiles the stage will use (`.lv-stage--idle`, `.lv-picks--idle`: a `ColonyThumb.drawIdle` each, animated while on screen, with the colony's rule and what it will read, in warning colour when it would sit out), a line on when the maps come and what happens next (`.lv-timeline`), after it the stage (`.lv-stage`: the three colonies as `.lv-pick` tabs with a `ColonyThumb` and their live leader, one `ColonyView` large, its share bars and follow card, then the Community roster). Below: verified in your browser and the per-colony table (`.lv-checks`), and the keepers' raw hashes and agents' posts folded in `.lv-more`.
- **Burn (`burn.html`, the Burn colony and the daily pot).** The Burn page opens with a compact head (`.page-head__split`: title beside the lede; the lede hides on phones), then the day strip across the width (`.day-strip`: day and phase, the bar from 00:00 to 24:00 UTC with a marker at 12:00, when stakes close and the seed is drawn, three steps under it in `.day-steps` with the current one lit, and the clocks). Under them, `.day-facts` holds the last pot (pick, burned and paid, verify link), the day seed and a link to the history.  The drop-sugar workbench follows the day strip in every phase (staking is the thing to do), and the colony section after it. The colony section is `.burn-grid` (stage two thirds, panel one third): from 00:00 to 12:00 the staking view (the nest, `.nest`, with every ant waiting and staker ants tinted, and today's stakers under it, beside the scent so far; no map, since there is no seed yet), or from 12:00 to 24:00 today's colony (the map beside one card with the leader and the trail share, then today's stakes). The drop-sugar workbench shows the menu as `.option-cards--list` and folds the scent comparison away in `.scent-more`. Then the pot sizes (a table of each size's base pick chance (the measured rate with no stakes, `BURN_BASE_PICK_PCT` in `web/burn.mjs`), burned part, reward part and sim handicap at today's treasury; each column heading has a `title` tooltip saying what it means), then the past pots (`.stats`, then a table with burned and to-stakers columns, today's staking or running row first). The token's facts (supply, burned, treasury, paid to stakers) and the top earners are information, not something to do, so they sit last in a folded `<details>` ('$ANTO facts').
- **Ants are clickable everywhere.** Every full colony map takes a click on an ant: Live's stage and the Burn map show a follow card (and a `.sim-frame__hint` until the first click), Replay and Recruit follow it in their own panels. Every stakers list is a `.roster` that spotlights its wallet's ants on the map beside it (on Burn before 12:00, in the nest: `.nest[data-spot]`, with `.is-new` ants popping in as a wallet's sugar arrives). On Live, the Community roster sits under the stage and its `.lv-pick` thumbnails tint staker ants.
- **Recruit** (`web/recruit.html`) opens on the composer (`.rq-compose`): two numbered steps (`.rq-step`) in one chamber, pick a market (Polymarket search, then the samples as `.market-card` radios with the keepers' odds per outcome) and add your forecast (`.mine-grid`, one percent field per outcome, with a sum status), beside a sticky summary (`.rq-summary`: account, market, odds, your forecast, the fee split as one `.fee-split` bar in neutral steps with a key, and the one primary button). The run section stays hidden until a request starts: a lifecycle strip (`.rq-track`, one dot per step with the current one lit and its full text under it), then `.rq-stage` with one colony large (each crank call starts its colony and the three run side by side at the Live pace; they show as `.rq-thumb` buttons above the map with their live leader, and the map shows any one of them, Momentum first) beside the swarm belief, hash and verify, then what the colonies read and who got paid (`.rq-after`). A skipped request hides the map and shows the refund. The page ends with a link to the agent tool on the Docs page, where `.rq-tool` shows it by role in `.seg` tabs, each with its copyable `.cmd` lines and the NEAR CLI call it signs.
- **Explanations live in Docs.** `web/docs.html` holds every explanation beside a sticky on-page index (`.docs`, `.toc` in three groups, the section in view marked with `aria-current`). It starts with the one-minute version (`.steps`, then `.uses` links), key words (`.glossary`, one card per term linking to its entry) and the page cards. Each section opens with its short answer (`.doc-section__gist`), and each term is an `.entry` (its anchor id, an `h3`, a one-line `.entry__gist`, then short lists, `.flow` numbered steps, a `.timeline` of clock times, a `.docs-table` or `.entry__note`). Write the short answer first and keep each bullet to one idea. Other pages keep a one-line lede and at most a short hint, and link the rest with a `.what` link (`whatHTML(anchor, label)` in `web/ui.mjs`) to a Docs anchor. When you add an explanation, add it to Docs and link it; don't add a paragraph to a working page.
- **Workbench.** Tool pages use `.workbench`: a wide stage beside a 320 to 400px panel. Replay puts the stage first, like an inspector. Sandbox, drop sugar (on the Burn page) and Receipts put the controls first (`--controls-first`), because you set something up and then watch. `.workbench__col--sticky` pins a panel only where it fits the viewport.
- **Prose** (`.lede`) is set in Fraunces. Mono is kept for UI, data, seeds and hashes.
- **Keyboard.** Every `Player` takes space (play or pause), ← and → (one tick), and Home and End.
